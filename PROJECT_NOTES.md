# Sirb (com.h.sirb)

Sirb is a desktop-only Chromium browser for video and large tab collections. Flutter owns the chrome; a local fork of webview_cef 0.6.2 owns real CEF Texture instances on Linux, Windows and macOS. SQLite stores sessions and histories in application support; shared_preferences stores onboarding and presentation preferences.

## Skills learned

- Flutter gen-l10n: ARB resources generate typed localization, Material delegates provide RTL; applied to root l10n/ and core/l10n. Read https://docs.flutter.dev/ui/accessibility-and-internationalization/internationalization.
- Responsive layout: local LayoutBuilder constraints, Expanded and constrained content avoid window-dependent assumptions; desktop workspace and settings. Read https://docs.flutter.dev/ui/adaptive-responsive/general.
- window_manager 0.5.2: initialize before window calls, minimum size and prevent-close listener; desktop lifecycle. Read package README/API and changelog.
- shared_preferences 2.5.6 and url_launcher 6.3.3: preferences are not crash-safe session storage, launching can return false or throw; settings and contacts handle both. Read both package READMEs/changelogs.
- icons_launcher exactly 3.1.0: platforms enable flags and dart run icons_launcher:create; assets/icon and desktop runners. Read README/changelog.
- Linux packaging: FPM directory inputs and architecture/dependency metadata, AppDir/AppRun, Flatpak SDK/runtime and build-bundle; packaging scripts. Read FPM cli-reference, docs.appimage.org manual, flatpak-docs first-build.rst.
- CEF embedding: off-screen Texture, separate browser hosts, switches before CefInitialize and WasHidden; fork common native code. Read webview_cef README/changelog/source and chromiumembedded.github.io/cef/general_usage.
- Blocking: OnBeforeResourceLoad runs on IO thread and RV_CANCEL prevents transmission; synchronized compiled rules and document-start V8 injection, CSS selectors scoped to hosts, defensive DOM observation for YouTube. Read CEF resource_request_handler.h and Adblock Plus filter writing guide.
- Resources: affinity applies to threads and is inherited across fork; use allowed CPU mask, Windows Job limits account descendants, systemd-run --user --scope -p MemoryMax= requires memory delegation; Mesa DRI_PRIME and NVIDIA PRIME env precede rendering. Read man-pages sched_setaffinity.2, kernel cgroup-v2, systemd-run, Microsoft Job Objects/SetProcessAffinityMask, Mesa envvars and NVIDIA PRIME Render Offload chapter.
- Tabs: hidden hosts retain state, closed hosts restore URLs and media time; bounded speculative hosts consume real resources and cannot evade quotas. Read CEF browser.h (WasHidden) and MDN preconnect; applied to tab and preloader services.
- SQLite: sqflite_common_ffi 2.4.3 runs operations on a worker isolate, use WAL and transactions with synchronous FULL for crash durability. Read package README/changelog; shared storage service.
- Codecs/sandbox: official CEF distributions must not be assumed to include licensed H.264/AAC; VP9/AV1/Opus tested separately. User namespaces are required for unprivileged AppImage; Zypak CEF requires ZYPAK_CEF_LIBRARY_PATH. Read CEF build documentation, browser API and Zypak README; build notes and runtime tests.
- Native interop: typed pointers/Struct and DynamicLibrary via dart:ffi, method channel marshaling, Flutter Texture registration; native fork and per-platform resource implementations. Read dart.dev/interop/c-interop and Flutter platform-channels.
- Desktop toolchains: CEF 149 requires C++20, Windows MSVC/CMake, Linux clang/ninja/GTK, macOS >=12 with Xcode/CocoaPods and helper embed hook; runners/build scripts. Read Flutter Linux/Windows/macOS building pages and webview_cef installation documentation.
- Isolates: ports transfer messages not shared mutable memory, FFI database factory already owns worker isolate; serialized snapshot writes. Read dart.dev/language/isolates and sqflite_common_ffi docs.
- Keyboard/reorder: SingleActivator handles platform modifiers; CallbackShortcuts and ReorderableListView implement browser accelerators and tab ordering. Read Flutter actions-and-shortcuts.
- Package verification: pub.dev API latest stable archive, SDK constraints and changelogs read before dependencies. Verified Flutter 3.47.7/Dart 3.13.5 supports the chosen versions. webview_cef lists all three targets; upstream Windows x64-only downloader will be extended for Arm64.

## Structure and binding development rules

core contains theme, l10n and constants; shared contains reusable models, persistence and engine contracts; features contain browser/tabs, ads, onboarding, histories and settings; platform contains concrete OS resource implementations; screens/desktop is the only targeted screen directory. Every new feature/change must be applied to all existing targeted screen directories (desktop only). Never end a session without checking this. No fixed interface text or colors in widgets; website titles, URLs, downloaded filenames and detected hardware are external data, not interface labels.

## Assumptions and decisions

Only desktop targets are generated. The specification's references to mobile/web adaptations apply only if targeted. /dist means the repository-root dist/ directory, not a privileged filesystem root. Shared browser instances share one persistent profile to preserve login. Media-playing tabs are exempt from tab-sleep and drawing suppression even when RAM is tight; the UI warns rather than interrupt playback. Pinned tabs remain eligible for sleep unless playing media. Speculation never crosses non-http(s) URLs and is bounded by RAM and live-instance budgets.

Search is DuckDuckGo-only in both the address bar and new-tab page; legacy search-engine preferences are ignored. Two-finger scrolling follows OS settings without an app override and refreshes when the window regains focus. New tabs are inserted immediately after their opener (or the active tab for toolbar/history opens); batches keep input order there. Editing shortcuts belong to the focused surface: only the CEF focus subtree may dispatch focused-frame Copy/Cut/Paste/SelectAll/Undo/Redo; Flutter owns new-tab search, address/find, tab search and dialog fields. Use exactly one CEF command for website keyboard/context-menu edits, never a concurrent execCommand/manual value insertion or asynchronous selection-to-Clipboard fallback. Preserve rich/contenteditable and cross-origin frame semantics. Native key hooks must reserve these chords for Flutter rather than also forwarding them (including physical macOS keys on non-Latin layouts). Linux CEF defaults to ozone-platform=x11 when DISPLAY exists and no explicit Ozone backend was supplied: the automatic OSR backend was measured to keep CEF clipboard text separate from GTK/Flutter, while explicit X11 shares the desktop selection. Respect explicit backend overrides and never require unavailable X11 on Wayland-only hosts; clipboard sharing on those paths is not verified. This launch-backend change requires restart. Website menus use common native CefContextMenuHandler hit-testing, not a second JavaScript-generated menu: retain view-relative DIPs, shadow-DOM links, native editable/selection state and cross-origin frame ownership. The document-start window capture listener reserves trusted contextmenu events before site handlers without preventDefault, allowing Chromium to produce exactly one native event; windowed game hosts retain the Chromium menu. Reject background events and actions whose source tab/controller changed while the menu was open. Secondary-button movement must not be sent as a left drag. During live resizing, Flutter fills the new viewport with the last CEF frame until the resized frame arrives. This avoids empty strips at the cost of transient scaling; actual texture dimensions still come from native paint events. The browser surface has no 3840-pixel display-width cap. Live resize requests are serialized and pending intermediate sizes coalesced in the shared Dart controller; sizes are cached only after native acknowledgement, and failures remain retryable.

Tab lifecycle is shared on all three desktops: only the latest activation epoch may continue hiding/showing hosts after an await, and activation iterates a snapshot of the tab list. Join the entire per-tab wake task (configuration/navigation/visibility), not just native create readiness. Sleep detaches its host and sets phase before native close, with per-tab retirement awaited before recreation; never write sleeping state after close or accept callbacks from a replaced host. Media-state snapshots have a two-second bound; unknown/stalled state retains the host rather than risking playback. A recorded renderer termination is runtime-only state: recreate that host on selection/retry, retaining the diagnostic. All desktop refresh/retry/shortcut/context-menu paths use BrowserController.reload so a missing/failed host can be restored and error UI cleared; healthy reloads retain their host/history. Do not infer failure from a white screenshot or empty page, disable sleep globally, force playback/focus, or weaken resource/media protection. Shutdown awaits pending host creation/retirement before engine shutdown. Native close removes the texture entry under the paint-map mutex, then releases it before CEF close and texture destruction/unregistration; holding it across those calls caused a measured dead-renderer disposal hang. CloseBrowser may reenter OnBeforeClose: erase/snapshot browser-map entries before invoking it, never keep an iterator across the callback.

Visible-content-first loading defaults on and suspends speculative video preloads without rewriting the saved preload choice. It adds native lazy-loading hints to images and known large content iframes, honours explicit eager/high-priority resources and leaves unknown-size utility frames alone. Parser-started requests, CSS backgrounds, shared payloads and arbitrary site fetches are not a universal viewport network filter. YouTube-only code lives in lib/features/youtube/services, independent of ad blocking: defer only positively identified off-screen watch-page /next continuation fetches, at most 16 and 15 seconds, preserving AbortSignal and cancelling stale navigation/pagehide work. Never defer /player, media segments, initial/mixed/unknown /next or unreadable Request bodies. Original-title preference defaults on and uses credential-free same-origin public oEmbed only for intersecting title cards/current heading, at most two low-priority requests, bounded per-document cache and timeout; it preserves search/UI language, handles SPA card reuse and restores replacements on opt-out. Public metadata can be unavailable or localized itself: do not promise universally original titles or change audio/subtitles. Both settings update live through the shared document-start/runtime policy on all three desktop targets; no ad-rule lists are changed.

Game mode suspends speculative video preloads without changing CPU/RAM quotas or protection of playing tabs; turning it off restores the saved preload choice only when visible-content-first loading is also off. With hardware acceleration and Automatic GPU selection, game mode prefers the discrete adapter on supported Linux/Windows dual-GPU systems at launch, without rewriting the saved GPU preference. Explicit integrated/discrete choices remain respected; macOS stays OS-managed. GPU policy changes require restart, never live migration or an FPS guarantee. NVIDIA PRIME on a hybrid Wayland desktop uses CEF X11/XWayland when DISPLAY is available to avoid fatal cross-adapter dmabuf imports; an explicit Ozone backend is preserved, and Wayland-only hosts are not forced to use unavailable X11. Early GPU/scope relaunch preserves startup URLs and drops stale wait-parent arguments. Graphics compatibility is opt-in and requires restart: SIRB_WEBGPU_ENABLED=0 disables Chromium WebGPUService while retaining hardware WebGL and GPU compositing, allowing compatible sites to choose their fallback. It is not a universal game fix (CEF OSR pointer lock remains unsupported; the explicit native game-window handoff below uses a different, real windowed host). Respect Chromium driver blocklists; do not force unsafe GPU features or advertise dual-GPU pooling/100% utilization. GPU badges describe saved preferences, not measured live adapter selection. Audio diagnostics observe existing WebAudio contexts weakly and never force resume/sample-rate/latency changes.

Native games use an explicit, localized menu/confirmation action that creates a Chrome-style CEF Views window inside Sirb; no pointer-lock state is spoofed and normal Chromium permission handling remains intact. Only HTTP(S) is accepted, at most one native game window (including pending creation) is allowed, and it shares the persistent request context and ad/configuration scheme. Successful handoff saves the source visit, clears speculation and disposes the original OSR host before resetting that tab to sirb:new, avoiding two loaded game heaps. A creation failure retains the original tab. Native windows count against live-host accounting, are not slept like ordinary tabs, and are not session-restored. Close the Views owner during app shutdown; never call CefShutdown with live browsers or bypass the existing close-timeout safeguard.

Manual media start is shared across Linux/Windows/macOS HTTP(S) documents: trusted local player pointer/click or playback-key intent unlocks only that media element. Normalize SVG/icon targets to their nearest button and scan at most six local ancestors (never body/root, stop on multiple media) so deeply nested custom play controls such as YouTube's bottom button are accepted. Do not restore the former four-level limit: real YouTube bottom-control input was rejected by it. Opening/focusing/promoting a tab, unrelated page activation and synthetic clicks do not unlock it. Native HTML autoplay is paused before consent; rejected script play() calls retain NotAllowedError semantics. Do not force play on activation or reset an already-consented element during live configuration/SPA updates. Utility about:blank/srcdoc and other non-HTTP(S) contexts receive neither initial nor live Sirb policy Eval; never add allow-scripts or disable frame sandboxing to inject there. Chrome extensions are disabled at engine startup on all desktop targets because Sirb has no extension consent/management UI; this prevents unsolicited system extensions such as Plasma Integration from injecting page scripts and does not disable the CEF V8 bridge. Changes to this native launch policy require restart. Site-origin sandbox warnings can still be legitimate and remain visible.

Diagnostics observe uncaught JS/rejections, console warnings/errors, resource/HTTP failures, permission rejection, media/API failures, worker events and WebGL/WebGPU loss. Observers preserve successful results and rethrow rejected operations, never grant permissions or force playback. The exact Sirb playback-consent denial and documented play/pause/new-load AbortError cancellations are excluded from fault storage (including Chromium's console echo); genuine codec/permission/network failures remain. RuntimeDiagnosticRouter also coalesces only cross-capture ResizeObserver echoes within one second in the same host/page/source, retaining the first diagnostic and subsequent same-path loops. It annotates deferred notifications as recoverable, not proof of a healthy layout. Native-confirmed ad cancellations retain their ad records without an extra DOM network-failure echo: exact source and host scope, two-second bounded evidence, at most 128 DOM errors delayed 150ms for bridge ordering, cleared on navigation/reconfigure/close. Never infer cancellation merely from an ad hostname/current rule; explicit HTTP/code/fetch/media failures and unconfirmed DOM errors remain. Flush pending genuine errors on reset/shutdown. Exact severity-warning Chromium unused-preload messages are performance advisories, not JavaScript failures: retain the first per host/page/resource within a bounded 30-second window and expose a localized Performance hints filter and All view. Error-only query/count/delete excludes performance hints, compatibility notices and ad records consistently; search/copy/export/all still include them, and existing historical rows are not rewritten. Do not remove site preload links, change their as/type, force fetch/playback or weaken focus/manual-start policies to silence advisory warnings. Exact Chromium no-adapter warnings normally remain graphics capability diagnostics, and sandbox-blocked about:blank scripts permission/protection diagnostics, not hidden or permission-granted. The two known native console messages on explicitly allowlisted HTTPS youtube.com/www.youtube.com browsing pages (home, watch, results, 11-character-ID Shorts, @handle channels and their known browsing tabs, and feed/subscriptions or feed/history) instead use the localized Compatibility and protection notices filter: severity-3 no-adapter probes require a matching YouTube page-path source (or the exact /live_chat_replay utility frame path under a /watch top page), and severity-4 about:blank sandbox blocks require the YouTube /s/_/ytmainappweb/_/js/ source prefix. Unknown routes, channel applications and Playables remain outside the allowlist. This narrow policy lives in features/youtube/services/diagnostic_policy.dart, retains originalCategory, original severity/source/message and advisory metadata, and does not apply to Playables/games, unrelated sites/scripts, extensions, error-level no-adapter messages, API permission denials or GPU-device/media/network failures. Notices stay visible in All, their own filter and search/copy/export; they are not proof of healthy playback. Neither classification changes WebGPU availability or repairs site-authored layout/sandbox code. Log-card category labels must wrap within their available width, including long localized notice labels at 800x600. Reused rejection objects are observed once per document, without preventing default or changing website catch behavior. Empty/missing src/href must not resolve into a false document-resource failure. Do not suppress genuine googlevideo HTTP failures or replay signed media URLs as a diagnostic fix. Native transfer failures retain HTTP status plus CEF requestStatus and receivedBytes; failed transfers after 2xx headers carry responseBodyTransferFailed metadata, not fake success or an assumed ad cancellation. These fields diagnose transport failure; they do not prove a remote CDN problem has been fixed. Serialized SQLite writes and stable pagination preserve older records; copy/export retrieves all matching rows, not only the first displayed 1,000. Payload fields are bounded, and log UI warns about privacy and visibility limits: site-hidden/caught custom errors and some worker failures can remain invisible. An empty log is not proof of an error-free page. Website console telemetry in native windows is restricted to runtimeError/adError; it must not forge lifecycle or popup commands. CDP remains opt-in and loopback-only for isolated testing, never enabled in normal preview launches.

## Release automation

GitHub Actions builds only supported 64-bit desktop targets: native Linux x86_64/aarch64, native Windows x64/arm64, macOS x86_64/arm64/universal. Never fabricate Linux armv7/i686 or Windows x86. Use the shared tool/release.py inventory/names: sirb-<version>-<system>-<arch>, 23 packages plus SHA256SUMS.txt. Validate ELF/PE headers and every macOS Mach-O/helper slice, never infer architecture from filenames. This Flutter's Windows command has no --target-platform flag: bootstrap native Dart through Windows batch/PowerShell, not MINGW's x64-only path. Linux/Windows ARM SDKs bootstrap from the pinned Flutter git revision; missing native artifacts fail rather than silently relabel x64. AppImage tool/runtime are version/hash pinned, with matching zsync update URLs. No cross-platform CEF/build cache reuse. Main/PR/manual runs upload short-lived Actions artifacts; tags must match pubspec version and exact source commit. Publishing uses only the job-scoped GitHub token, a complete verified inventory and server SHA-256 checks before taking a draft public; never replace a published release or retarget an existing version tag. macOS public releases require Developer ID signing and successful app/DMG notarization/stapling; unsigned/ad-hoc CI DMGs are development artifacts only. Windows packages are currently unsigned and must be labelled accordingly. Signing keys stay in temporary runner storage. All macOS CEF consumers, including the CocoaPod target and standalone helpers, must match the wrapper's CMake NDEBUG/DCHECK configuration (Release/RelWithDebInfo/MinSizeRel define NDEBUG, Debug does not); mismatches reference missing debug-only symbols and change the ref-counted ABI. Full setup and limitations: docs/RELEASE_AUTOMATION.md. Only desktop UI is targeted; build automation adds no screen or interface text.

## CEF distribution preparation

Linux/Windows share third_party/webview_cef/third/download.cmake and validate_cef.cmake. Never trust version.txt alone: validate required nonempty runtime/resources, exact pinned CEF header version and platform-specific wrapper/header inventories from the distribution's generated CMake source lists. Repair damaged caches automatically using a TLS-verified, published-checksum-checked archive in a sibling staging directory. Check extraction exit status and extracted layout/contents before version-stamping/promotion; keep the old cache on failure, serialize preparation, and recover interrupted promotion. Do not mask missing CEF sources by omitting them from the wrapper target, adding stubs, upgrading unrelated Dart dependencies or deleting the tracked fork. Canonicalize the existing cache parent before lock/staging/extraction: Windows Flutter path plugins have symlink ancestors that libarchive refuses to extract through. Never disable that extraction protection. Retry transient transfers at most three times, deleting partial responses before each fresh attempt; never resume/extract an unverified partial archive. Keep CMake helpers compatible with the plugin's minimum 3.10. Hermetic regression command: python3 tool/test_cef_download.py; native Windows/macOS/Arm64 builds still require matching hosts.

## Streaming codec compatibility

The official Linux CEF 149 runtime was measured with H.264=false, AAC=false and actual MP4 DEMUXER_ERROR_NO_SUPPORTED_STREAMS even with ad blocking/focus loading off; VP9/Opus advances normally. Do not attribute every Twitch #4000 to ad rules or promise Kick playback from generic video fixtures. No codec-enabled engine binary is supplied/verified yet. Optional SIRB_CEF_ARCHIVE_DIR selects trusted local full Standard Distribution archives plus bare SHA-256 sidecars for all six desktop platform/architecture targets; source digests participate in Linux/Windows raw and macOS prepared-framework cache identities. Missing configured artifacts, invalid hashes or mismatched versions fail instead of falling back. Never swap unrelated libcef/libffmpeg binaries or spoof isTypeSupported/canPlayType to advertise support. Review codec licensing/patent obligations. Full build/integration instructions: docs/STREAM_CODECS.md.

Main-frame Twitch/Kick capability reports are read-only, independent of shield settings and localised in the sole desktop screen target; ephemeral missing-codec state resets on full navigation/handoff and is not session-restored. Settings report AVC and AAC separately. tool/verify_stream_codecs.py verifies the actual Sirb document-start policy and native MP4/MSE frame progression with a VP9/Opus control; --require-h264-aac is a failing release gate until real decoders work. Native HLS, DRM, live-service/account/region availability and ad removal need separate evidence; a checksum/source filename is not codec proof. Only use opt-in loopback CDP and isolated test profiles.

## Ad-rule maintenance

Shared ad rules and composition live in lib/features/ads/ad_rules.dart. Maintain YouTube, Twitch and Kick independently in lib/features/ads/sites/{youtube,twitch,kick}_ad_rules.dart: bare host names, ECMAScript URL regexes and valid scoped CSS selectors. Defensive YouTube scripts stay in its own module; no duplicated rules in C++. Never block all googlevideo.com, ttvnw.net, live-video.net, playback APIs or authentication; these carry desired content too. Twitch/Kick modules conservatively suppress identifiable client-side ad endpoints/slots; they do not remove server-inserted segments or promise ad-free live streams. Keep ad countdowns and playback controls visible. YouTube work is coalesced, observes only player ad-state attributes and seeks at most once per finite ad source/episode; do not reintroduce document-wide class observation or private resize calls. Cosmetic rules must not hide media elements or wrappers containing them. Reuse the existing cosmetic style node and change its text only when CSS changes; unchanged live policy updates must not remove/reinsert the sheet or rewrite an unchanged color scheme. Opt-out/site exceptions remove the sheet. This avoids browser-induced layout churn without patching website ResizeObserver callbacks or promising all site layout loops are fixed. Global video priority hints preload=auto once per document for a large intersecting video without an explicit preload policy (at most 32 observed candidates; save-data/speculation opt out), and on local player intent. Explicit site policies remain until interaction. It never forces autoplay, load(), seeking, focus, bitrate, or quotas; MSE players retain segment-buffering control. Runtime policy is shared by all three desktop platforms. YouTube player-envelope cleanup covers JSON.parse plus successful same-origin exact /youtubei/v1/player and /next Response.json()/XHR JSON results, and known bounded playerResponse/player_response/response/args wrappers (including serialized player responses). Preserve videoDetails/streamingData, native parsing/abort failures, response metadata, media bytes and shield/site-exception opt-out; do not replace fetch/XHR, rewrite signed playback URLs or perform unbounded recursive data walks. Platforms can change ad delivery and anti-adblock behavior; no universal or permanent ad-free guarantee is made. Retest logged-in/out playback, live/VOD/clip seeking, site exceptions and shield toggles after every rule change.
